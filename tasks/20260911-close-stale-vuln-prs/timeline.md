- User request arrived garbled via voice transcription ("forecast" instead
  of nothing meaningful). Asked a clarifying question; user confirmed

- Investigated repo: no "forecast" concept exists anywhere. Found 12 open
  PRs (#27–#38), all auto-generated by `.github/workflows/vulnerability-scan.yml`,
  all titled identically, going back to 2026-06-15 — clearly stale
  duplicates from a workflow that never closes its own previous PR.
- Asked user to confirm scope (close existing PRs now vs. fix workflow vs.
  both). User chose both.
- Root cause: the "Try to fix vulnerabilities and create PR" step in
  `vulnerability-scan.yml` always creates a fresh timestamped branch/PR with
  no check for an existing open PR from a prior run.
- Plan: (1) close PRs #27–#38 via `gh pr close` with an explanatory comment,
  (2) add a step to the workflow that closes any previous open PR with the
  `vulnerability` label + matching title before creating the new one.
